**The first e2e run failed with timeouts (617 passed, 10 failed):**

- Every failure was `page.goto … waiting until "load"` running out of time.
- The Playwright traces show why. Some `/_next/image` requests under `next start` never resolved: `hero-banner`
  w=1920, and scene w=1024/1440. `hero-banner` is an asset this branch does not change.
- A cold request for the same key via curl is fine: 0.5–1.7 s, including concurrent duplicates.
- The trigger was a new sweep test in this branch. It hops across 32 pages quickly, which aborts cold optimisations
  part-way through. After an abort, later requests for that key hang, and the hang spreads to later specs.
- The fix: the sweep now answers `/_next/image` inside the browser (`page.route`), since the box sizes come from CSS
  alone. The next run and the final run were fully green.
- **Watch for this on the merged full suite.** The hang itself is behaviour of `next start` in this environment and
  is not specific to this branch. Any test that navigates away mid-optimisation on a cold cache can trigger it.

Bundle: no client JS changed. `scene-opener-frames.ts` is imported only by the server `SceneOpener` and by tests.
