### How the tests were made honest (no exclusions, no lowered thresholds)
- **The shared `axe` fixture** (`tests/e2e/fixtures.ts`) now calls `revealForAudit()` before it analyses a page. That function waits for `networkidle`, scrolls each `.reveal` that has not fired into view, waits until every `.reveal` is revealed and fully opaque, then restores the scroll position. Without this, axe measured contrast on content still at opacity 0 (17 nodes on `/`, 6 on `/about`). This is the approach the brief asked for: audit what a reader actually sees, and exclude nothing. The `networkidle` wait was added after `/about` at w390 failed once. The `.reveal` class is only added after hydration, so it could appear in the middle of a scan.
- **The EVAL-011 crawler** (`tests/e2e/crawler.ts`) caught a real false-dead that `visibility: hidden` had been hiding. The six How I think pills link to `/work/<slug>#0N-…` chapter anchors. Those ids are mounted on the client when a URL hash points into the deep dive (OverviewToggle, TP8), so they are not in the static HTML. The crawler used to hide these pills. Now it checks them, and it first flagged all 12 as dead. The fix: when the static body lacks the id, the crawler opens `url#hash` in a scratch tab and waits up to 5 s for the id to attach. A wrong anchor still comes back dead, because the id must exist after a real load. `how-i-think.spec.ts` @EVAL-011 already asserts that these pills resolve.

One more intermittent failure: `artifacts.spec.ts` ChapterNav "click scrolls to the anchor" at w1024 failed once, in an intermediate full run (846 > 200). It passed in the other two full runs. This is the known Lenis click-without-scroll flake that TKT-90b is fixing (bug 3, `lib/focus.ts`). This ticket does not touch it.

### Regression tests
- `tests/e2e/a11y-90d.spec.ts` (new):

The test also asserts the last `.reveal` has not fired, which proves it really is checking the pre-reveal state. A separate test checks that focus entering a Reveal reveals it at opacity 1.

  - **A11Y-4:** every `.dec-why` reads `^Why: \S`.
  - Playwright 1.63 has removed `page.accessibility.snapshot()`, so these tests use `locator.ariaSnapshot()` and `getByRole` instead.
- `tests/unit/work-grid.test.tsx` (+3 tests):
  - `WorkIndex` never imports `motion/react`, `framer-motion` or `@/lib/motion`. This guards the bundle size.
  - The first paint has no `data-enter` or `data-exit`.
  - When the filter changes, new items fade in, and removed items are held with `inert` and `aria-hidden` for 150 ms and then dropped.

## Decisions (EXE-20 delegated authority)
1. **/work crossfade: hand-rolled CSS, not View Transitions.** `FilterTabs` owns the URL change, and it is off limits (TKT-90b). A View Transition would have to wrap `router.replace` there. The CSS version keeps both halves of Design §4 (fade-out 150 and fade-in 200), is opacity-only, and adds 0 kB of motion code.
2. **A11Y-2/3: CSS alt text instead of `aria-hidden`.** Both glyphs are `::before` content, and alt text is the CSS way to hide generated content from assistive technology. Browsers without alt-text support keep the old plain `content`, which is the old behaviour and still valid.
3. **Reveal: `:focus-within` plus `onFocus`.** The CSS covers the first frame, and the attribute keeps the content revealed after focus moves on. Reduced motion shows `.reveal` immediately instead of waiting for a scroll.
4. **The axe and crawler test changes** make the scans measure the real rendered state. Nothing is excluded or loosened.
