## 5. EVAL-011 — dead controls (Critical FAIL, root-caused)

**Symptom:** `.eval/dead-controls.json` → `{controls: 278, ok: 264, warn: 12, dead: 2}` — both `dead` entries are `/about` (w390 + w1440), `kind: "unknown"`, `name: "(error)"`, `detail: "classify threw: elementHandle.evaluate: Execution context was destroyed, most likely because of a navigation"`.

**Root cause (traced via the failing test's `trace.zip`, `1-trace.trace` — extracted and read call-by-call):** the crawler visits `/about`, then clicks each in-page button via `observeButtonEffect()` (`tests/e2e/crawler.ts` line 279). One `TimelineNode` toggle button (`aria-expanded: "false"` before click) is clicked; its `onToggle` correctly opens the `StoryCard` and syncs the URL via `window.history.replaceState(null, "", "#experience-<id>")` (`components/timeline/ExperienceTimeline.tsx`) — a deliberate, spec'd, non-navigating deep-link pattern (already proven correct by the real `timeline.spec.ts` assertions in §4). `observeButtonEffect()`'s "did anything change" heuristic does a raw string compare of `location.href` before/after the click; `replaceState` legitimately changes that string (adds the hash), so the heuristic reports `urlChanged: true` and calls its own recovery step, `page.goBack({ waitUntil: "load" })` (crawler.ts line 360), to "undo the navigation." But `replaceState` never pushed a history entry, so `goBack()` instead pops the crawler's own prior **real** navigation (its `page.goto()` sequence through `/`, `/work`, `/work/teachspark`) — a genuine full-page navigation away from `/about`, which destroys the execution context for every other already-queried `ElementHandle` on that page. The next control in the enumeration loop then throws exactly the observed error, and `crawlControls`'s catch-all records it as a fabricated "dead, unknown, (error)" control (crawler.ts line 525).

**Verdict:** this is a **test-infrastructure false positive**, not a product/functional defect — the ExperienceTimeline hash-sync behavior it's tripping over is itself correctly implemented and independently verified passing by `timeline.spec.ts`. It is specific to `/about` because `ExperienceTimeline` is the only interactive component in this milestone whose correct behavior includes a `location.href`-changing, non-pushState side effect.

**Not fixed here** (would require an implementer's judgment call on the right heuristic — e.g., compare `history.length` before/after to distinguish real navigation from `replaceState`, or ignore hash-only URL diffs, or drop the `goBack()` recovery in favor of a fresh `page.goto(route)` before continuing the loop) — flagging per the "report defects, don't fix them" QA-tester brief. This is Critical-priority per `evaluation-plan.md` and currently fails the automated gate for real (script exits 1); it must be fixed and the eval rerun before this milestone can cleanly PASS.
