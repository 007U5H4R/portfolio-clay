- `Design.md`: Dev-60–63.
- Tests: `tests/e2e/ask-panel.spec.ts` (rewritten), `tests/e2e/eval-007.spec.ts` (the keyboard answer path), `tests/unit/ask-tushky-grounding.test.ts` (new), `tests/unit/eval-021.test.ts`, `tests/unit/paper.test.tsx`; `tests/unit/ask-panel-quick.test.ts` deleted (the Dev-49 chips are retired).

**2. Drawer width:** `clamp(400px, 32vw, 460px)`.

| viewport | drawer width |
|---|---|
| 1440 | 460 px |
| 1366 | 437 px |
| 768–1249 | 400 px |
| < 768 | 100vw full-screen |

It is fixed at top/right 0 with `100dvh`. The page stays visible on the left under a navy 38% backdrop with a 2 px blur.

**3. Animation:** CSS, not `motion/react`. The native top-layer `<dialog>` has to stay open until the slide-out finishes, so close is sequenced imperatively. CSS also keeps the global reduced-motion collapse and EVAL-010's computed-style checks valid.
- **Open:** `data-open` is set one frame after `showModal()`. The keyframe runs `translateX(100%) → -4px → 0` over 420 ms with `cubic-bezier(.22,1,.36,1)`; the last step is the paper settle. A 12 px paper strip past the right edge hides the settle gap.
- **Close:** a `data-closing` keyframe, 280 ms, `translateX(0 → 100%)` with no bounce, then `dialog.close()`.
- **Backdrop:** fades in over 240 ms.
- **Tushky:** a one-time mascot entrance (opacity, scale .97 → 1, rotate -1° → 0). The avatar breathes only while an answer is loading. Nothing loops once the drawer settles.

**4. Empty-state structure:**
- **Header:** Fraunces "Ask **Tushky**" plus a terracotta paw, 36 px. Caveat subtitle "Tushar's Portfolio Assistant" with a rust hand underline. A 44 px round close button.
- **Mascot row:** the aria-hidden annotation "I sniff through Tushar's work so you don't have to.", the 124 px mascot, and the one taped sticky note (Caveat, aria-hidden, with an sr-only Inter twin so it is announced once).
- **Intro card:** "Hi! I'm Tushky." followed by the spec copy.
- **Suggestions:** "Try asking…" above six single-column rows, each with a 32 px pastel icon circle and an arrow.
- **Composer:** pinned at the bottom.
- **Short heights:** at `max-height: 860px` the mascot drops to 96 px and the rows to 48 px, so 1366×768 and 1024×768 fit without scrolling.

**5. Chat state structure:**
- `useAskChat()` holds `messages: ChatTurn[]`. A turn is either `{role:'user', text}` or `{role:'tushky', status: loading|answer|empty|error, query, answer}`, and `isGenerating` is derived from them.
- Every turn is answered by the same retrieval-only provider with the 150 ms skeleton floor. Answers stay the verbatim entry text.
- Once the first question is asked, the dog, the intro and the list collapse. The header shrinks and gains a 40 px avatar.
- Tushky bubbles sit on the left with a 32 px avatar, a DraftTag where the entry is a draft, the answer text, "Sources from portfolio:" link chips (the evidence titles), and "Ask next:" chips (2–3, derived from the sources) on the latest answer only. User bubbles sit on the right with a light rust tint.
- Error turns offer "Try again". Empty turns show the fallback plus the index's own suggestions as chips.
- The view auto-scrolls so the newest question sits at the top: smooth normally, instant under reduced motion. Closing the drawer resets the conversation.

**6. Typography changes:**

| element | style |
|---|---|
| Title | Fraunces 600, 36 px (28 px in chat, 30 px on phones) |
| Subtitle / "Try asking…" | Caveat `data-hand="label"`, 22 / 24 px |
| Intro | 19 px headline, 15 px body |
| Rows, bubbles, input | 15 px, line-height 1.55 in bubbles (14.5 px at short heights) |
| Chips | 14 px |

Every text size is ≥ 14 px (EVAL-008).

**7. Responsive behaviour:**
- **≥ 768:** the right drawer.
- **< 768:** full-screen. The page is hidden behind it, the torn edge and shadow are dropped, the title is 30 px, the dog is 84 px, the "sniff" annotation is hidden, the sticky note is compact and inline beside the dog, the cards are full width, and the composer sits above `env(safe-area-inset-bottom)`.

**8. Accessibility behaviour:**
- `role="dialog"` (native `<dialog>` plus `showModal()`), `aria-modal="true"`, `aria-labelledby="ask-tushky-title"`.
- Native focus trap. The page is inerted by `lockBackground`.
- Esc, the close button and a backdrop click all take the same animated close path. Focus returns to the trigger that opened the drawer (the header ghost, the MobileMenu row, or TKT-108's hero CTA through the same `triggerRef` + `openPanel()`).
- Focus lands in the composer on open and stays there after each question.
- The conversation is a `role="log"` / `aria-live="polite"` region, with sr-only "You:" / "Tushky:" prefixes.
- All controls are ≥ 44×44 with the rust focus ring (the composer field shows it via `:has(:focus-visible)`). Icons are aria-hidden; card names are the question text; Send is named "Send".
- Reduced motion: no slide, no settle, no mascot entrance, no pulse or typing animation, no hover lift, no smooth scroll.

**9. Compromises and calls:**
- **Attachment button omitted (Dev-61).** Tushky can't read files, and a paperclip that does nothing would make a false promise.
- **Two suggestions are remapped (Dev-63).** "Show me his product thinking process." submits the `discovery` prompt, and "Walk me through a specific project." submits `most-technical` (RailCite). As worded, both matched the product list. Tushar's wording is what the card and the user bubble show.
- **"AI / cloud" has no cloud entry.** It answers from `ai-products` (score 0.67).
- **"Compare his experience" is not offered.** It returns the empty fallback.
- **The grounding note replaces the S7 microcopy line inside the drawer**, and is not repeated in the chat (spec: "do not duplicate").
- **Answers read in first person** ("I've shipped…") because the answers are verbatim portfolio text; they were not rewritten, to keep the no-fabrication invariant.
- **Card rows are 48 px on short screens** instead of the spec's 54–60 px, so the whole empty state fits 768-px-tall laptops.
- **The z-index 0/40/50 stack is the browser top layer**, which also keeps the drawer above TKT-106's parallax layers.
- **The user's own words now render in their bubble** as a React text node, never as HTML. Round 1 never echoed the query.
- **Bug found while testing (and fixed):** `lockBackground()` inerts every `header` element, so a `<header>` inside the drawer made the close button unclickable. The drawer header is a `<div>`.

**Right-drawer root cause (fixed).** Closing only removed `data-open`. That removes the open keyframe and changes `transform` in the same style change, and Chrome sometimes skipped the transition. At 768 and 1024 the drawer then vanished in place instead of sliding right. Closing now sets `data-closing`, which runs its own 280 ms `translateX(0 → 100%)` keyframe; the dialog closes after it. The e2e samples every frame of the close from inside the page: the drawer's translateX only ever increases and never goes negative (no bounce).

**Other checks and notes**

To make it open the drawer, it has to set `triggerRef.current` and call `openPanel()` from `useAskContext()`, as `AskAIButton` does. That file belongs to TKT-108 / TKT-113, so I didn't change it.
