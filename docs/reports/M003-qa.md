## 4. Gate verdict

**FAIL**

Everything gate-named in the QA brief is green: the full suite (typecheck/lint/unit/content-gate/forbidden-strings/tokens), the gate-critical EVAL set (EVAL-001 6/6 both widths, EVAL-007 focus-trap for AskPanel + MobileMenu at 390/1440, EVAL-006/008/010/011/012/013), and 18 of 20 applicable M-003 test cases. The one real, non-accepted failure:

- **TC-051 (P1) — AskPanel bottom-sheet is 38px narrower than the viewport at <768 widths**, letting the page behind show through a visible gap on the right edge. Root cause identified precisely (missing `max-md:max-w-none` override on the native `<dialog>`, unlike the sibling `MobileMenu` component which already has it). This was not caught by any existing automated case — TC-051 has no automated Playwright coverage today, and the existing EVAL-008 "no horizontal overflow" checks don't catch under-fill (only overflow). One-line fix, easily verified with the same measurement approach used here.

Everything else, including the 23 apparent `pnpm test:e2e` failures and the `pnpm eval` EVAL-007/EVAL-008 "FAIL" lines, was run down to a confirmed root cause (host resource contention under full 4-project parallelism, causing trace-artifact write races, not real assertion failures) and reproduces 0 failures when rerun with reduced parallelism — recorded here as an infra/host finding, not a code defect, and not counted against the verdict.

## 5. Recommendation

1. Fix TC-051 (add `max-md:max-w-none` to `components/ai/AskPanel.tsx`'s dialog className) and add automated coverage for AskPanel geometry at all 4 breakpoints (currently untested).
2. Consider capping Playwright `workers` (or running the 4 viewport projects sequentially) in CI/local full-suite runs on this host — the current `fullyParallel: true` with no worker cap produces spurious `[w1440]` timeouts/trace-write errors under load, as reproduced twice in this gate.
