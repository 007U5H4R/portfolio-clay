## 5. QA-005 (NEW) — Analytics/Speed-Insights console errors under local `pnpm start`

**Symptom:** Playwright `tests/e2e/smoke.spec.ts` → `"home loads with no console errors"` (tagged `@smoke`, the console-error half of the TC covering technical-plan.md A12 observability + A13's "no silent client errors" table) **FAILED** for the first time this gate — the one `unexpected` result in the eval's own Playwright run (`.eval/playwright.json`: `expected 686, skipped 801, unexpected 1, flaky 0`):

```
Refused to execute script from 'http://127.0.0.1:3000/_vercel/insights/script.js' because its
MIME type ('text/plain') is not executable, and strict MIME type checking is enabled.
Refused to execute script from 'http://127.0.0.1:3000/_vercel/speed-insights/script.js' because
its MIME type ('text/plain') is not executable, and strict MIME type checking is enabled.
```

**Root cause, verified by direct reproduction** (`pnpm build && pnpm start`, then `curl -sI http://127.0.0.1:3000/_vercel/insights/script.js`): the route 404s locally (Next serves its own 404 HTML for the unrecognized `/_vercel/*` path — these are Vercel-edge-only reserved paths, not application routes) and the browser refuses to execute the response as a script. `app/layout.tsx`'s own inline comment (line 65–68) states Analytics/Speed-Insights are "**no-op off Vercel** (they render nothing and inject no script when not served by the Vercel platform)"; `docs/reports/TKT-50.md` §2 makes the same claim ("the only modes these components activate outside `next dev`" are "production/preview"). **Both are incorrect for this library version:** `@vercel/analytics@2.0.1`/`@vercel/speed-insights@2.0.0` gate script injection on `NODE_ENV=production`, not on "served by Vercel" — so any production-mode `next start` off the Vercel platform (exactly this QA gate's own procedure, and TC-104/106/108/110/113/etc.'s test harness) injects the `<script>` tags and hits a real 404.

**Impact assessment:** this will **not** reproduce on the actual Vercel deployment (the `/_vercel/insights/*` and `/_vercel/speed-insights/*` paths are real, proxied endpoints only on Vercel's edge — TKT-50 §1 already confirmed this by reading the same package source for the CSP `connect-src` work), so it is not a user-facing production defect. It **is** a real, deterministic regression against the `@smoke` console-error gate for every local `pnpm eval` / `pnpm test:e2e` run going forward, and it falsifies the stated rationale in both `app/layout.tsx` and `docs/reports/TKT-50.md`.

**Not fixed here** (QA-tester logs, does not fix) — options for the orchestrator: (a) gate `<Analytics/>`/`<SpeedInsights/>` behind `process.env.VERCEL` so they no-op under bare `next start`, matching the comment's actual intent, or (b) scope `smoke.spec.ts`'s console-error allowlist to these two known-Vercel-only paths with a comment explaining why, or (c) accept as a documented local-only env caveat (EVAL-004-style) if the team decides the automated gate itself should only run against a real deployment. Recommend (a) — cheapest, and it also makes the existing code comment true. **Logged as `QA-005` (new), Priority P2** — not blocking this gate (no product/production impact), but must not be silently folded into the pre-existing accepted-risk register without an explicit decision.
